# 0011. The journal, the state directory and the log

Status: accepted. Date: 2026-11-12.

## Context

A window can stop at any moment: a signal, a crash, a kill. What it replied before it stopped must still hold after it starts again: every receipt it returned, every delivery it queued and nobody fetched, and every sequence number it took (`restart-reproducible`). `mediator.Reload` (record 0008) rebuilds a mediator from values; something must keep those values on disk, in an order that a crash at any point leaves consistent, and read them back without deciding anything. The receipts on disk are also the evidence a third party verifies and the log is made from (`journal-is-evidence`, `log-from-receipts`). Each party keeps its own record beside it, so that reconciliation can show what a journal left out.

## Decision

- **The journal is a directory**, mode 0700, that the window locks with an exclusive `flock` on its `accord` file while it runs; a second window on it is `journal-locked`. It holds `accord` (the Accord id, the card hash, the mediator and the founding time, written once), `receipts.jsonl` (each receipt as the mediator returned it, one per line, made empty at the first start just before `accord`, so that a founded journal always has one and a reader can refuse a directory that has none), `questions.jsonl` (each ask's question, deadline and roles, never a byte of its part) and `held/` (each delivery not yet fetched, in a file named by its receipt's id, with the answer call beside it where it has one, record 0010). The formats are written in `adapters/journal`'s package comment; they are door formats, not frozen ones.
- **Every write is synced before the reply** (`journal-synced`), in this order. A pass: its held file, then its receipt. An ask: its questions line, from `mediator.Question` under the mediator's reference, then its receipt. An answer: every held file it queued, then all of its receipts in one write, so that a crash rarely leaves an answer without its release. A tick or a reload's closings: their receipts. A get: the removal of the held file, and the directory synced, before the reply. A write that fails ends the window with the failure and no reply; the next start reloads what the disk holds.
- **Reading is not judging.** At start the journal adapter reads the files and hands `mediator.Reload` what they hold: the receipts in order, the questions lines of the questions still open, found by `receipts.Releases` (since `questions.jsonl` keeps every ask), and each held delivery alone, its answer call left in the file. Every check of what was read is Reload's. When Reload refuses, the window stops with tool error `journal`, naming the file and the line, from the index Reload gives, and the core's code; the journal is left byte for byte as it was.
- **The only repairs.** A last line of `receipts.jsonl` with no line feed was never answered, and is the one change ever made to that file: it is removed, with a line on stderr. A last line of `questions.jsonl` with no line feed was never written either, and is removed. `verify`, `log` and `reconcile` read `receipts.jsonl` without the lock and write nothing: a directory without one is tool error `journal`, and a last line with no line feed is left out with a line on stderr saying the file was cut there, so a reader sees it. Besides these, the two clean-ups Reload documents: a questions line whose question is in no receipt line is left in the file, not handed on, and noted; a held file whose receipt is in no line never crossed, and is removed, with a line on stderr, once Reload has taken the rest, so that a start that stops changes nothing.
- **The state directory** of a party, by default `<key file>.state/<Accord hex>/`, holds `actor`, `lock`, `seq`, `envelopes.jsonl`, `delivered.jsonl` and `kept.jsonl`. Every socket command holds its exclusive lock from before it reads `seq` until the reply is handled (`state-lock`); `give --wait` lets it go while it waits. An envelope's line is written before its call is sent, and removed only when the call is refused, so a submission lost with the window shows as missing. `seq` is written only after a reply, so the next give takes the seq above both `seq` and the highest envelope line: a give the window journaled whose reply was lost never has its seq used again, which the mediator would refuse; the protocol lets a seq skip numbers. A last line of any of the three files with no line feed was never written: reads leave it out, and the lock removes it, with a line on stderr, before anything is appended.
- **Kept parts.** Under `--keep`, and for every delivery a wait fetches, a party writes the part to `kept.jsonl`: a part it gave as its message's exact bytes beside the receipt, and a part it fetched, or a version it gave as an answer, as the delivery holds it, with the answer call beside it. A decider's comments are always kept by the decider, since only the giver's copy can show which question a comment was about.
- **The log** is made by `adapters/export` from `receipts.jsonl` and any number of state directories. It verifies the receipts first and prints no row when they fail or when `receipts.Releases` refuses them. One row per question, in the order asked; the answer, the times and the release come from receipts alone, through `receipts.Releases`; the topic, the comment and the texts only from kept parts a verified receipt covers, by the envelope's hash for a part given and by the salted digest for a part fetched; `answer_signed` only after a kept answer call verifies under the row's answerer, for the row's question and action and for the digest's text. A kept part no receipt covers is left out with a line on stderr. CSV cells that start a spreadsheet formula are prefixed with `'`.

## Consequences

- A window killed between two calls carries on with the same receipts, chains and sequence numbers; a question open at the kill is closed by one receipt at the next start, and a delivery not yet fetched is fetched once.
- A delivery's body, a released proposal or a changed version included, lies in clear in `held/` until it is fetched, and so does its answer call. Encryption at rest is not in this version.
- A crash after a held file is removed and before the fetch is answered loses that delivery; its receipt stands, and reconciliation shows it as unrecorded.
- The log adds nothing a receipt did not record: with no state directory it still shows every answer and release.
