# 0006. The mediator holds an Accord's state and runs its operations

Status: accepted. Date: 2026-11-12. Amended by records 0020, 0021, 0022, 0023 and 0025.

## Context

The capability packages decide: the canonical form, signatures, founding, composition and receipts are each a function of their inputs. Something must hold what those decisions leave behind, between one operation and the next, for one founded Accord: the receipts written, the chain of each pair, each sender's highest accepted sequence number, what is queued for each receiver, and the parts held as questions. It must run the door's check table in order, call composition for the verdict, have receipts build each receipt, and change its state only after every receipt of an operation is built. It is the one role package of the core (`packages-by-adr`), and it must hold no capability's logic (`mediator-no-logic`).

The door's check table covers crossing-1 to crossing-4 and crossing-6: the crossing message, the part, the envelope and their order. These read the mediator's state as they go (its members, its Accord id, each sender's highest seq), and no capability package of the core is named for them.

## Decision

- **`core/mediator` holds one Accord's state.** A `Mediator` holds the founded Accord, the mediator's key, every receipt written in order, the last link of each ordered pair's chain, each sender's highest accepted `seq`, a queue of deliveries per receiver, and the open questions in the order they were opened. One goroutine owns it; its methods are not safe for concurrent use.
- **Its names**, by signature:
  - `func Found(set []byte, key signing.Key, at string) (*Mediator, error)`: founds the set by `setup.Found`, and refuses with `ErrOtherMediator` a set whose `mediator.actor` is not the key's reference (setup-contract-7), a sentinel because no set is wrong for it (`sentinels-uncoded`). A founding refusal is `setup`'s `*Error`, returned as it is.
  - `func (m *Mediator) Give(caller string, message, envelope []byte, at string) (Outcome, error)`: the door's twelve rows in order, then `composition.Decide`, then `receipts.Build`, then the state. `type Outcome struct { Verdict, Reason, ReceiptID string; Receipt []byte }`.
  - `func (m *Mediator) Get(caller string) ([]byte, error)`: the first delivery queued for the caller, as the canonical bytes of `delivery.json`, or nil when none is queued. The queue drops its reference to a delivery as it hands it out, so the mediator keeps no body or salt of it once fetched (crossing-3).
  - `func (m *Mediator) Receipts() [][]byte` and `func (m *Mediator) Pending() []string`: the reads a scenario's end state needs, as copies (`results-are-copies`). `func (m *Mediator) Accord() string` and `func (m *Mediator) Card() string`.
  - `func (Mediator) Format(f fmt.State, verb rune)`, `func (Mediator) GoString() string` and `func (Mediator) String() string`: a `Mediator` holds the mediator's key and every part it queues or holds, so it prints as one fixed text under every format verb, as a value or a pointer (`secrets-never-print`). The methods take the value, so a copy prints the same.
  - `type Rejection struct { Code RejectionCode }` with the door's twelve codes and section 6's two, what the caller did wrong; `type Error struct { Code ErrorCode }` with `CodeAt`, a time off the timestamp rule, and `CodeInternal`, a receipt the mediator could not write, what the caller's program did wrong or what failed inside (`rejection-vs-error`). `const Extension`, `RoleAgent`, `RoleUser`, `SaltBytes` (record 0020).
- **The door's rows are one operation of the mediator.** They run in the order of section 4's table and stop at the first that fails; nothing of the message is read before the envelope's signature verified under the caller's key. They are written as one function that reads the mediator's state, not as a package of their own: each row reads a member or the state, and decides nothing composition or receipts decide. A rejected give returns before any state is touched (crossing-7).
- **A receipt before state.** `Give` builds the receipt, and the delivery or the question it leads to, and only then appends the receipt, advances the pair's chain and the sender's `seq`, and queues or holds the part. No test can stop the core between the two, since it does no I/O; the reviewer reads it in the code.
- **Asking** (maybe-1). A give decided `escalate` writes its crossing receipt and holds a question under that receipt's id: the asker, the receiver, the part as its delivery would carry it, the echoed envelope, the subject, the agreed rule, and the deadline, the give's time plus the rule's timeout, at most `9999-12-31T23:59:59Z`. Nothing is queued. The question also keeps the role labels of its rule, the roles that may answer it.
- **Closing a question** (section 6). A question closes once, in the call that writes its closing receipt, and an answer that releases writes its release receipt in that same call, after the closing and before any state changes (`release-in-resolve`). An accept's answer and a change's version are each a part the mediator forms; each is decided by its kind through `composition.Decide`, as a part formed by the mediator, like any give (`one-decision-module`). A release after an accept decides the held part again, as given, from the asker to the receiver: a `block` is written as composition returns it, and any other verdict is the answer's pass, written `pass`, `ok` (maybe-10). The mediator compares no stance and adds no verdict of its own. The names, by signature:
  - `func (m *Mediator) Resolve(caller, questionID string, r Resolution, at string) ([]Outcome, error)`: an answer. Section 6's three rows in order, `not-a-member`, `no-open-question` and `not-an-answerer`, then the caller's own inputs, then the receipts: the resolution receipt's outcome, then the release receipt's when one is written. `type Resolution struct { Action Action; Answer string; Salt []byte; Release bool }`, with `type Action string` and `Accepted`, `Changed`, `Declined`, `Cancelled`, spelled as the vector format's actions. `Answer` is the answer's text or the version; `Salt` is the salt the mediator's caller minted for it. A decline or a cancel reads neither, nor `Release`. A `Resolution` holds an answer's text and salt, so it prints as a fixed text under every format verb (`secrets-never-print`).
  - `func (m *Mediator) Undeliverable(questionID, at string) (Outcome, error)`: the finding that nobody can be reached to answer. Row 2 only.
  - `func (m *Mediator) Tick(at string) ([]Outcome, error)`: the passing of time. Every open question whose deadline is at or before `at` closes, in the order the questions were opened, each `timeout` at its deadline (maybe-5). It refuses nothing.
  - `func (m *Mediator) Answerers(questionID string) ([]string, bool)`: an open question's answerers, the members whose bindings give them one of its roles, in actor-reference order; an empty list, not nil, when nobody holds one, and `nil, false` for an id that names no open question.
  - `func (m *Mediator) Queued(receiptID string) (Queued, bool)`: a copy of the delivery the receipt queued, while it is unfetched, and the member it is for. `type Queued struct { To string; Delivery []byte }`, the delivery's canonical bytes as `Get` would return them. A `Queued` holds a body and a salt, so it prints as a fixed text.
  - `func (m *Mediator) Result(caller, questionID string) ([]Outcome, bool, error)`: a closed question's closing receipt and its release receipt, when it has one, to its asker only. A stranger is `not-a-member`; another member, an open question and an id that names no question are `nil, false`. It reads the receipts with `receipts.Releases`, so it gives the same answer after a reload.
  - `func (m *Mediator) Question(caller, id string) (Question, bool, error)`: a copy of an open question, `type Question struct { ID, Asker, Receiver, Kind, Form, Deadline string; Roles []string; Part []byte }`: its id, its asker, the receiver its part is for, the part's kind, its body's form (`text`, `raw` or `data`), its deadline, the role labels that may answer it, and in `Part` the body's value as given, without its salt (a text's bytes, a raw body's decoded bytes, a data body's canonical bytes). It is read by two callers only. The mediator's own reference reads any open question before membership is asked: the door that serves the mediator journals each ask's deadline and roles from it before the ask's receipt, so that a reload takes them from the journal and decides nothing again (record 0008), and a question nobody can answer is journaled like any other. Every other caller goes through section 6's rows in order: a stranger is `not-a-member`; a closed or unknown id is `false` with no error, as `Resolve` tells a stranger to the role nothing of a closed question; and a member who is not one of its answerers is `not-an-answerer`. So an answerer can be shown the part it is asked about, which maybe-1 allows, while no door matches terms or holds a body of its own (`one-decision-module`). A `Question` holds a body, so it prints as a fixed text under every format verb and never prints `Part` (`secrets-never-print`). Added with the door, record 0010.
  - `func Reload(...)`, `type Open`: record 0008.
  - The rejection codes `NoOpenQuestion` (`no-open-question`) and `NotAnAnswerer` (`not-an-answerer`).
- **The caller's misuse** (`rejection-vs-error`). An answer's own inputs are checked after section 6's rows, in this order, and a failure is an `*Error`, not a `*Rejection`: an action that is not one of the four, `action`; an accept or a change with a salt of fewer than 16 bytes, `salt`; a change with an empty version, `answer`. Each writes nothing and leaves the question open. A time off the timestamp rule is `at`, before any row, as for a give.
- **`Error`'s codes and fields.** `Error` is `struct { Code ErrorCode; Index int; Err error }`. Besides `at` and `internal`, its codes are `salt`, `answer` and `action` (above); `unfounded`, an operation on a `Mediator` no `Found` or `Reload` made; and reload's `journal`, `held` and `question` (record 0008). `Index` is the index of the receipt or entry at fault where the code has one, and -1 where it has none; its text is the package, the code and the index, never an input. `Err` is set for `journal` alone, to the verifier's `*Error`, and `Unwrap` returns it.
- **A `Mediator` no one founded.** Every method of a zero-value `Mediator` that has an error result returns `*Error` `unfounded` and panics on nothing: `Give`, `Get`, `Resolve`, `Undeliverable`, `Tick` and `Result`. `Question` returns `*Error` `unfounded` too. Of the reads, `Answerers` and `Queued` find nothing, and `Accord` and `Card` give the empty string.

## Consequences

- Two mediators founded from one set, with one key, at one time, and given the same operations at the same times, write the same receipts byte for byte (receipt-10). Nothing here reads a clock or mints a salt.
- A vector can test a give end to end through one mediator, and a door adds only what touches the world: the socket, the clock, the journal.
- The door's rows live beside the state they read. A reviewer checks that none of them compares a stance, matches a term or builds a receipt.
