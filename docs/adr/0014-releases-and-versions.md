# 0014. Releases and versions

Status: accepted. Date: 2026-11-23.

## Context

A release is what outside users get, so it has to be provable from the start: anyone should be able to check a binary's signature and provenance, and rebuild it to the same bytes, and a user holding a binary needs to say which build it is. A one-line install runs before anything has checked it, so it must refuse what it cannot check rather than install it. A Go project outside placket should be able to require the core by a tagged version, and the root module should build against what such a project gets. `docs/release.md` holds the steps.

## Decision

- **What a release holds.** A GitHub release of the tag `vX.Y.Z`: one `.tar.gz` archive per platform, Linux and macOS on amd64 and arm64, each holding the binary, `LICENSE`, `NOTICE` and `README.md`; an SPDX SBOM per archive; `install.sh`, the one-line install; `checksums.txt`, the SHA-256 of every archive and SBOM, and of `install.sh`; its cosign bundle; GitHub's build provenance for every archive and for `checksums.txt`; and the Homebrew cask, `placket.rb`, written after `checksums.txt` is signed, whose every SHA-256 is an archive's line there.
- **Signed without a key.** cosign signs `checksums.txt` with the release workflow's own GitHub identity, and the provenance uses the same identity. So there is no key to keep, and anyone can check that an archive came from placket's release workflow on `main`. The checks pin the exact certificate identity and issuer, with the source ref `refs/heads/main` and GitHub's own runners only. The bundle uses cosign's new bundle format, read by cosign 2.4 and later.
- **Reproducible.** The archives rebuild to the same bytes from a git clone at the tag: every time inside an archive is the commit's, and the build sets `GOTOOLCHAIN` to the version of `go.mod`'s `toolchain` line, because that line is only a minimum and a newer local Go builds other bytes. The SBOMs carry their own creation time, so they are signed through `checksums.txt` but are not reproduced.
- **A release is a merged release pull request.** A release pull request moves `CHANGELOG.md`'s `Unreleased` section under the new version and marks the register's formats released; approving it is the decision to release. `scripts/release-detect.sh` reads each push to `main` and says whether it is a release. It refuses a release while the repository is private, and does so only for a push that would release, so the workflow does not fail on every push before placket is public. A tag pushed by hand starts nothing.
- **The release workflow.** `.github/workflows/release.yml` runs a release on the push that merges a release pull request, and resumes one whose run failed. On every pull request it builds a snapshot twice without signing and compares the archives. It pins its actions by commit, and GoReleaser, cosign and syft by version.
- **`placket version`** prints, on standard output since the version is its result, `version`, then `commit` and `commitTime` when the build carries them, `go`, and `module`, the decision module as `placket card --default` names it. `--json` prints one object of the same members. The version is the one Go stamps from the git state: the tag at a tag, a pseudo-version at another commit, `+dirty` for a tree with changes not committed, and `(devel)` for a build with no git information. It is read from the build info, never set with `-X`. The command is a row of the requirement text's command table.
- **`install.sh` installs only what it could check.** It installs nothing when it cannot check the signature on `checksums.txt`, for want of `cosign`, unless `PLACKET_INSTALL_UNSIGNED=1`, that variable and only that value, says to go on; it then says the signature was skipped, and ends by saying the binary's origin was not checked. A mirror, `PLACKET_RELEASE_BASE`, is checked as the release is, signature first. The version asked for is the version installed: `--version vX.Y.Z` names the one archive taken, an empty `--version` is refused, and it replaces an installed `placket` only with a binary whose `placket version` is that archive's. The reason is that `curl | sh` runs the script before anything has checked it, and an install that goes on without the signature would put a binary on the machine that nothing tied to the release workflow; with the signature, the archive's line in `checksums.txt` ties the archive to it. `docs/release.md` says how to check `install.sh` itself before running it.
- **The core is tagged `core/vX.Y.Z` by the maintainer, by hand.** The release workflow tags only `vX.Y.Z`. Until the core is first tagged, the root module requires it at `v0.0.0` and replaces it with `./core`; once it is tagged, the root requires a tagged version, with no `replace` (`root-module`), so that the root builds against what a Go user outside placket gets, and a Go project can require the core's promised names by a tag.

## Consequences

- A user can check a release with `scripts/release-check.sh`, or by hand with the steps in `docs/release.md`, and rebuild it.
- Changing the pinned GoReleaser, cosign or syft may change the archives' bytes, so each lands in its own pull request.
- A version number whose release push was refused is released by taking its section back under `Unreleased` and adding it again, or by releasing the next version.
- A machine with no `cosign` installs placket only when its user says to go on without the signature, and is told what that leaves unchecked.
