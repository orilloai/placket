# What the checks print, and what they miss

What `make ci` prints, and what the checks that read the tree can and cannot see. The rules themselves are in the topic files beside this one, each under its public name.

## What `make ci` prints

Every step of `make ci` is a target of its own, so `make <rule>` runs one check. The checks that read the tree are the rules of the checker in `tools/guard/`, built once by the step `guard`.

- A check of the tree prints `<rule>: ok` when it passes. When it refuses, every line it prints starts `<rule>: <file>`, with `:<line>` where the fault has a line, or is an indented detail line under one, and its last line is `<rule>: refused: <why> (docs/rules/<file>.md#<rule>)`, which links the rule's heading. `schemas-hold` first prints one count line per schema that holds, `schemas-hold: <schema>: ok, <n> accepted, <n> refused`.
- A toolchain step (`vet`, `lint`, `vulnerabilities`, `race`, `fuzz-seeds`, `coverage-reported`) prints `<step>: ok`, or `<step>: <module>: refused` after the tool's own output. `secrets` is described under its own heading below. `race`, `fuzz-seeds` and `coverage-reported` read one shared test run per module, the step `tests`, with the race detector and coverage, that also runs every fuzz test on its seed corpus.
- Every step then prints its time on a line of its own, `time: <step>: <n>s`, whether it passed or refused. No time fails a step.
- Only the lines of a check of the tree, and of `secrets`, promise to name a file. The other steps' lines name a module, a vector or a shell test, or nothing at all: the time lines, the `== <module>` and `== <test>` lines, the shell tests' own output, the shared run's and the runner's lines, and `ci-stays-fast: refused: make ci inside make ci`.
- `make ci` runs its steps side by side, `CI_JOBS` at a time: by default the host's processor count, and at least 2. It holds back each step's output and prints it whole when the step ends, so a step's lines and its time line stay together. `CI_JOBS` also sets how many shell tests run at once, and the step `tests` runs the modules' test runs half as many at a time, rounded up, and at least two when `CI_JOBS` is 2 or more. `make ci CI_JOBS=1` runs serially: the steps one by one, the shell tests one by one, and the modules' test runs one by one.

## Secrets

The step `secrets` runs gitleaks, pinned in the `Makefile`, over every file of the tree but `.git/`. It prints `secrets: ok`, or a line per finding, `secrets: <file>:<line>: <kind of secret>`, never the secret itself, and then `secrets: refused: no secret is committed (docs/rules/checks.md#secrets)`. No rule of `docs/rules/` is named for it: a committed secret is refused wherever it is.

## Known limits of the checks

The checks that read the tree are rules of one Go program, `tools/guard/` (`docs/adr/0004-how-a-change-is-checked.md`). It reads Go with the standard library's parser and resolves names without types; it reads `go.mod` files, the `Makefile`, scripts and the requirement text as lines. What that sees, and what it still misses:

- Every rule reads every `.go` file in its scope, whatever its build constraints, and refuses a file it cannot parse, at the line of the error; no file is skipped. Code `gofmt` would rewrite fails `make ci` anyway, in the `modules` step, which reads every Go file of a module outside `testdata/`.
- The checker does not follow a symbolic link, and the Go tool does. So every check of the core, and `product-words-once`, refuses a link anywhere under `core/`, `core/` and `core/go.mod` included, and `vectors-independent` refuses one under `vectors/`.
- An import path written with an escape, such as `"\x6fs"` for `os`, is refused by `core-imports` and `core-no-world` whatever it spells, and by `vectors-independent` in a generator: a reader of the text would not see the path the Go tool reads.
- A comment is never code, and a string is never an import: `"panic("`, `"os"` or an adapters path inside a string that is not an import path passes. `core-no-world` refuses cgo (`import "C"`) and every non-Go source file outside `testdata/`.
- `core-no-world` refuses the packages it names by import path, under any name. The calls of `time` it names, and `fmt.Print*`, are refused wherever they are referred to, called or not, through whatever name the file imports `time` or `fmt` under; a dot import of either is refused itself. `os.Getenv` and `os.Open` are matched by the name `os` too. Names are resolved without types, so a local variable that shadows an import's name is read as the package: a false positive, and the fix is another name.
- `print`, `println` and `panic` are refused as calls of the built-ins. A call through a selector, such as a field `s.print(...)`, passes, and so does a call of a function the package declares at its top level under that name, in a file of the same package clause that every build includes: no `//go:build` or `// +build` line, no system or architecture suffix such as `_linux` or `_amd64`, and a name that does not start with `_` or `.`. A name declared only in a file some build leaves out does not count, and the call stays refused, since that build calls the built-in. So a package that declares its own `print` only for some systems has its calls refused: a false positive. A parameter or local variable of that name is read as the built-in: a false positive too.
- `core-no-world` allows `fmt.Fprint*` and `fmt.Sprint*`: writing to an `io.Writer` the caller passes in is not printing, and the core cannot reach `os.Stdout` without importing `os`. A standard-library call that reaches the world inside itself, from a package the rule does not name, is not matched; the reviewer catches it. Among them: `time.LoadLocation` reads the time zone files, `ed25519.GenerateKey(nil)` draws from `crypto/rand`, `filepath.Glob` and `filepath.WalkDir` read the file system, `maphash.MakeSeed` draws a random seed, and `context.WithTimeout` reads the clock.
- `vectors-independent` reads a generator's imports, and refuses a string literal that spells the path of a package its group tests. A package reached through another package is not seen (`vectors/README.md`, Known limits).
- `constants-once` reads only the string literals that hold `placket.tech/` or `vnd.placket`, in the files built into `core/` and `adapters/`. Any other constant retyped, such as a minimum length, or a verdict or a reason another package already exports, is not seen; the reviewer catches it.
- `constants-once` and `claims-stop-at-crossing` read string literals as written, escapes included; a constant built from pieces, or a word spelled with an escape, is not seen. `product-words-once` reads a literal's value.
- `recipes-core-only` reads the imports of every Go file under `recipes/`, test files included and `testdata/` aside, and refuses an import path written with an escape. It does not follow a symbolic link, which `no-hidden-text` refuses when tracked; an adapter reached through another package is not seen.
- `machine-rules-in-ci` reads each `uses:` key of a workflow under `.github/workflows/` as written on one line: alone, after a list's dash or in a flow mapping, its name bare or quoted. A key or value split across lines, written with an escape, or reached through a YAML anchor or alias is not seen; an action that a local action under `.github/actions/`, or a workflow of another repository, uses in turn is not seen. It reads each `go run` and `go install` as written, and a tool named by a `make` variable from its assignment in the same file; a version spelled through a shell variable or another program is not seen. It reads `ci`'s prerequisites as literal target names: a variable there names nothing.
- `ci-stays-fast` reads each line of a `.sh` or `_test.go` file. It misses a clear spelled through a variable (`unset "$v"`) or another program, and a `make ci` reached in some way that loses the environment; the workflow's timeout backstops it. A Go `Env` list set on a line that does not name `os.Environ()` is refused, even when the list was built from it elsewhere: build it on that line.
- `no-hidden-text` reads every file git tracks outside `.git/` and `testdata/`, character by character, and skips a byte that is not valid UTF-8. A file git does not track, ignored or not, is not read until it is added. Where the root is not the top of a git work tree, or git cannot list its files, it reads every file there. It refuses the bidi controls (U+061C, U+200E, U+200F, U+202A to U+202E, U+2066 to U+2069), the variation selectors (U+FE00 to U+FE0F, U+E0100 to U+E01EF), every format character (Unicode's category Cf, the tag characters among them), and the characters outside that category that show as nothing, such as the Hangul fillers. It refuses a NUL byte at the first line that holds one and reads that file no further, so a tracked binary gives one line. It refuses every tracked symbolic link outside `testdata/`, since it does not follow one. A character that is visible but looks like another, such as a Cyrillic letter in Latin text, is not seen.
- `docs-tree-holds` reads the tree's entries as lines of the form `- [<title>](<path>)`, a page's links as inline links `](<target>)` and reference definitions `[<label>]: <target>` outside code spans and fenced blocks, and an anchor against the headings GitHub's slug gives, a repeated heading's with `-1`, `-2` and on. A link in raw HTML, or one built across lines, is not seen. It reads the CLI reference's command headings, flag rows and argument rows as `adapters/cli/gen` writes them. It reads a command line as a shell splits it, up to its first pipe, list, redirection or comment, a line ending in a backslash joined to the next; a line that does not itself start `placket `, such as one after `&&` or behind a variable, is not checked, and a word the shell fills in may stand for any value or flags.
- `agents-md-short` reads a rule's heading as a Markdown heading whose whole text is one name in backquotes, in a file directly under `docs/rules/`, and the index as its lines of the form ``- [`<name>`](<file>.md#<name>)``. It resolves a link to a heading of `docs/rules/` written as a path ending `rules/<file>.md#<anchor>` in a Markdown, Go, shell, make or workflow file, and ``](<file>.md#<anchor>)`` between the topic files, against the anchors GitHub gives their headings. A Go test is not read, since the checker's own tests plant broken links; a link spelled any other way is not seen.
