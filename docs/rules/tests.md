# Tests and vectors

How tests compare, where their helpers live, how the conformance vectors stay independent of the code they test, and how a change shows its tests red against `main` and green at its head.

## `tests-exact`

Every test compares exactly: the exact string, the exact code, `t.Fatalf` where the test cannot go on. A `strings.Contains` where the whole value is known, or `err != nil` where the code is known, is a finding.

Why: a loose test passes on the wrong answer.

Checked by: the reviewer.

## `raw-bytes-in-hex`

A test about raw bytes spells them in hex or `\x` escapes and checks them by comparing bytes, never by trusting an editor.

Why: editors normalise bytes silently.

Checked by: the reviewer.

## `test-helpers-placed`

A `_test.go` file holds nothing production code needs, and a helper two packages' tests share lives in `core/internal/testing/`, added when a third copy would appear and not before.

Why: test code should not become an unreviewed second API.

Checked by: the reviewer.

## `vectors-independent`

A vector's expected value never comes from the code it tests. Its generator imports no package its group tests, a check in `make ci` enforces that, and a planted fault in a tested package must change no regenerated byte. A landed vector changes only with a format version note.

Why: a vector written by the code under test proves only that the code agrees with itself.

Checked by: `make ci`: the step `vectors-independent` refuses a generator that imports a package its group tests, and `tests/test_vectors_independent.sh`, in the step `scripts`, plants faults in the packages each group tests and checks that no regenerated byte changes. The reviewer checks that a landed vector changes only with a version note.

## `runner-no-silent-pass`

A part of a vector the runner cannot run is never a pass. A pending part fails the run, and so does a vector the coverage list names that the runner cannot find.

Why: a green run must mean every case was run.

Checked by: the runner enforces it, in `make ci`'s step `runner-no-silent-pass`.

## `coverage-reported`

Coverage is reported, never gated; the number in a pull request comes from CI.

Why: a gate invites tests written for the number.

Checked by: `make ci` reports it, step `coverage-reported`.

## `schemas-hold`

Every frozen format's schema compiles as JSON Schema draft 2020-12 from the tree, with nothing fetched; its accepted examples validate and its refused examples are refused; and every schema file is named by a row of the register.

Why: a schema no example tests, or that the register does not name, drifts from the text unseen.

Checked by: `make ci`, step `schemas-hold`.

## `fuzz-parsers`

Every function that parses untrusted input has a fuzz test, seeded from the vectors. A door format has no vectors, so its parser's fuzz test is seeded from the format's own test cases.

Why: a parser meets hostile bytes first, and a fuzz test finds the input no one thought to write.

Checked by: the reviewer; the existing `fuzz-seeds` step of `make ci` runs each one on its seeds.

## `red-green-tests`

Every test a change adds or changes fails without the change's code and passes with it, and no test is removed or skipped unexplained, however the branch's commits were cut. The check reads two commits only: the base, the merge base with `main`, and the head. It runs each added and changed test at the base, with the head's test files laid over it, and then at the head. It refuses an added test green on base, a removed or newly skipped test, a test that does not run and pass at the head, and a change to non-test Go code under `core/`, `adapters/`, `cmd/`, `recipes/` or `tools/` with no test added or changed. A test that does not build at the base counts as red, and is printed as red (build). Three trailers on any commit of the change excuse an honest exception, each with its reason: `Green-On-Base: <test>: <why>`, `Test-Weakened: <test>: <why>` and `No-Test: <why>`. A trailer that names a test the change does not touch is refused. A changed test green on base, a test behind a build tag, changed helpers and every excuse are reported for the reviewer.

Why: a test proves the code only if it fails without it, and a removed or skipped test proves nothing; the shape of a branch's commits proves neither.

Checked by: the workflow's `red-green-tests` job checks it on every pull request and every push to `main`, with `main`'s copy of `tools/redgreen/`, so a change cannot alter its own judge; `make red-green-tests` runs it from a checkout. `docs/adr/0013-red-green-tests.md` records why and what it cannot see.
